<decisions>
Locked for this task — implement exactly, do not re-litigate:

- **D-01 — Free text, no E.164.** Column is plain nullable `text`, no CHECK constraint, no length constraint in SQL, no normalization. Human-typed Israeli formats ("03-555-1234", "052-123-4567") round-trip as typed.
- **D-02 — No backfill.** Existing rows (the 12 seed demo doctors and anything created before this ships) keep `NULL`. No placeholder, no default.
- **D-03 — Permissive validation only.** Optional; when supplied and non-blank, the ONLY checks are: it is a string, and its trimmed length is at most 20 characters. No Israeli-phone regex, no digit-only rule, no prefix table.
- **D-04 — Blank means NULL.** `undefined`, `null`, `""`, and whitespace-only all mean "no phone" and are stored as `NULL`. A non-blank value is stored TRIMMED. This deliberately diverges from plan 04-03's `availability_slots.reason` precedent (stored byte-identical, trim used only to test blankness): that precedent exists because D-04 of that phase demanded a byte-identical round-trip. No such requirement exists here, and surrounding whitespace on a phone number carries no meaning.
- **D-05 — Plain text on the public page, never a link.** The phone renders as a text node. No `href`, no dialer scheme. Consistent with T-hb3-05 and with the zero existing `tel:` matches in the codebase.
- **D-06 — Public exposure is limited to the single-doctor profile endpoint.** `doctor_search_view` and `GET /api/doctors` (the search list) are NOT modified. Recreating the search view for a cosmetic field is out of scope and would touch plan 03-01's locked 13-column shape.
- **D-07 — Admin surface stays English-only.** The Phone label in components/admin/** is a literal. Only the PUBLIC profile label gets dictionary keys.
</decisions>
