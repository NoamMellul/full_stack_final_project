# Quick Task 260818-s44: Doctor Phone Number Field Summary

**Nullable `public.doctors.phone` end-to-end: shared optional-field validation, admin create/edit form + table column, and conditional plain-text display on the public patient-facing doctor profile with Hebrew i18n.**

## Performance

- **Duration:** ~40 min
- **Tasks:** 3
- **Files modified:** 10 (1 new migration, 1 new spec, 8 existing files)

## Accomplishments

- Added `public.doctors.phone` (nullable `text`, no constraint) via a live-applied migration; no RLS/grant change needed since the table carries no column-level GRANTs
- Extended `lib/validation/doctor.ts` with a shared `validatePhoneValue` helper, wired into both `validateDoctorInput` and `validateDoctorPatch`, enforcing the 20-character cap server-side (not just client-side)
- Admin create form, edit dialog, and doctors table all gained a Phone field/column (English-only literal, matching the admin surface's existing no-`t()` convention)
- Public `/doctors/[id]` profile now shows the phone conditionally as plain text (never a link/href), with the number kept LTR under the Hebrew RTL layout via a `dir="ltr"` span
- 18 new Playwright test cases across create, edit, and public-display behaviors, plus a 55-test regression sweep (doctor-phone, admin-doctor-crud, doctor-profile, admin-doctor-status, admin-pagination) — all green

## Task Commits

Each task was committed atomically:

1. **Task 1: End-to-end phone on the create path** - `5e862b9` (feat) — migration, validation, POST route, admin create form + table column, 4 create-path Playwright tests
2. **Task 2: Admin edit path** - `ca09e29` (feat) — PATCH route, edit dialog wiring, 3 edit-path Playwright tests
3. **Task 3: Public profile display, i18n, and regression sweep** - `533c6e7` (feat) — public GET route, page render, dictionaries, `createTestDoctor` fixture option, 4 public-display Playwright tests, full regression sweep

## Files Created/Modified

- `supabase/migrations/20260818120000_add_doctors_phone.sql` - nullable `phone text` column, applied to the linked remote project
- `lib/validation/doctor.ts` - `PHONE_MAX_LENGTH`/`validatePhoneValue` shared helper; wired into both validators; `phone` added to `EDITABLE_KEYS`
- `app/api/admin/doctors/route.ts` - `DOCTOR_LIST_SELECT`/`RawDoctorRow`/`toListRow` carry `phone`; POST inserts trimmed value or NULL
- `app/api/admin/doctors/[id]/route.ts` - same select/row/mapper changes; PATCH stores trimmed value or NULL only when `phone` key is present
- `app/api/doctors/[id]/route.ts` - `PUBLIC_DOCTOR_SELECT`/`RawDoctorRow`/`toPublicDoctor` carry `phone`; deliberate omissions (`profile_id`, `is_active`, `created_at`) and the `is_active` filter left unchanged
- `components/admin/doctors-page-client.tsx` - Phone `Input` in `DoctorFormFields` (create + edit), Phone `TableHead`/`TableCell`, `FIELD_BY_MESSAGE` entries for both new server messages, `TABLE_COLUMN_COUNT` 7→8, `editPhone`/`setEditPhone` state + diff in `buildEditPayload`
- `app/doctors/[id]/page.tsx` - `phone` on `DoctorProfile`, conditional render in the muted details block using `t("doctor_profile.phone_label")` and a `dir="ltr"` sibling span, never wrapped in an anchor
- `dictionaries/en.json` / `dictionaries/he.json` - `doctor_profile.phone_label` ("Phone" / "טלפון") inserted alphabetically
- `tests/e2e/helpers/reference-data.ts` - `createTestDoctor` gains an optional `phone` fixture field (purely additive)
- `tests/e2e/doctor-phone.spec.ts` - new spec, 18 test cases across 3 `describe` blocks (admin create, admin edit, public display)

## Decisions Made

- **D-01/D-02/D-03/D-04/D-05/D-06/D-07** — all locked in the plan and implemented exactly (free text, no backfill, permissive length-only validation, blank=NULL/trim-on-store, plain-text-never-linked, search view untouched, admin surface stays English-only). No re-litigation.
- **Task 1's edit-dialog placeholder:** `DoctorFormFields` gained a required `phone`/`onPhoneChange` prop pair in Task 1 (shared by both the create form and the edit dialog), but Task 1's own file scope only wires the create-form call site — its `<verify>` step (`npx tsc --noEmit`) requires every call site to compile. Passed an inert `phone=""` / `onPhoneChange={() => {}}` placeholder at the edit-dialog call site in the Task 1 commit, replaced with real `editPhone`/`setEditPhone` state in the Task 2 commit as the plan specifies. Not a deviation from the plan's intent — a mechanical consequence of one shared component being touched incrementally across two atomic commits.
- **Task 2 test fixtures:** Task 2's two "existing phone" edit-dialog test cases need a doctor row that already carries a phone, but `createTestDoctor`'s `phone` option isn't added until Task 3 (per the plan's own file-scope split). Set the phone directly via `testAdminClient().from("doctors").update(...)` in those two test setups instead of touching `reference-data.ts` early — keeps Task 2's commit scoped to its own file list; Task 3 later adds the fixture option those tests could optionally have used.

## Deviations from Plan

None — plan executed exactly as written. The two items above are execution-sequencing details (not scope, behavior, or architecture changes) made necessary by splitting one shared component across two atomic task commits; both are documented for traceability.
