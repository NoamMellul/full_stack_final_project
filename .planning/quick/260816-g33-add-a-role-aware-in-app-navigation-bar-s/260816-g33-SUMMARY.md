# Quick Task 260816-g33: Add a role-aware in-app navigation bar Summary

Added a role-aware in-app navigation bar to the site header — an inline link row on `sm` and up, and a
Popover-based hamburger menu below `sm` — so a patient, doctor or admin can move between every page their role
owns by clicking, from any page in the app, with no URL typed by hand. Closes the "hyper problématique"
usability gap surfaced during Phase 06 UAT.

## What Changed

- **`components/site-nav.tsx`** (new): client component exporting `SiteNav`, taking `role: "patient" | "doctor"
  | "admin" | null`. Two module-scope constants — `NAV_LINKS` (per-role link arrays) and `ANON_LINKS` (single
  `/search` entry) — drive both an inline `<nav aria-label="Main navigation">` (`hidden ... sm:flex`) and a
  `Popover`-based `data-testid="site-nav-menu"` mobile menu behind a `Menu`-icon hamburger button. Each link sets
  `aria-current="page"` when its href matches the current pathname via `usePathname()`. Mobile links call
  `setOpen(false)` on click.
- **`components/site-header.tsx`**: added the `SiteNav` import, an explicitly narrowed `role` constant (compares
  `profile?.role` against the three literals, falls back to `null` — never a raw cast), and wrapped the logo link
  + `<SiteNav>` in one flex div. The existing single `profiles` query is unchanged; no second round trip.
- **`dictionaries/en.json` / `dictionaries/he.json`**: 11 new `nav.*` keys each, inserted alphabetically between
  `languages.he` and `notifications.appointment_booked.doctor`, per the plan's locked table. 214 keys total in
  each dictionary, key-for-key symmetric.
- **`tests/e2e/site-nav.spec.ts`** (new): 11 tests across 2 tasks — see Verification below.
