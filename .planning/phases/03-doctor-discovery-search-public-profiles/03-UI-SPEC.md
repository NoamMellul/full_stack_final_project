# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase surface (per objective):** Public, unauthenticated patient-facing pages — `/search` (multi-filter doctor search: name, specialty, language, neighborhood, availability date range, numbered pagination, sorted by soonest availability) and `/doctors/[id]` (public doctor profile: full details, "demo profile" indicator, read-only upcoming-slots list with a disabled non-functional "Select this slot" control per D-18). No booking, no auth, no doctor/admin UI in this phase — those are Phases 4/5 and already-shipped Phase 2 respectively.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized in Phase 1 — `components.json` present, do not re-init) |
| Preset | `base-nova` style, `neutral` base color, `cssVariables: true`, `rtl: true` — unchanged from Phases 1-2, reused for design-system continuity |
| Component library | Base UI (`@base-ui/react`) — **not** Radix, confirmed by `components/ui/button.tsx` / `badge.tsx` |
| Icon library | `lucide-react` (already installed) |
| Font | Geist Sans (UI text) / Geist Mono, via `next/font/google` in `app/layout.tsx`; `--font-heading` maps to the same `--font-sans` variable — single family across body and headings, no separate display font |

**No new primitives required this phase.** Every component needed already exists and is installed: `button`, `card`, `badge`, `input`, `select`, `skeleton`, `label`. No `npx shadcn add` command needed. The availability-range filter uses two native `<Input type="date">` fields (same pattern as `app/admin/appointments/page.tsx`), not a new date-picker primitive.

**No shadcn `Form` wrapper** (same as Phases 1-2): plain primitives with manual React state and manual validation functions (per the project's no-Zod convention). This phase's "forms" are read-only filters, not data-mutating forms — there is no submit/save flow to validate beyond query-param shaping.

**RTL note:** `rtl: true` remains active. All new layout/spacing classes (filter toolbar, result cards, pagination controls, profile layout, slot chips) must use logical properties (`ps-`, `pe-`, `ms-`, `me-`, `text-start`, `text-end`) — never physical (`pl-`, `pr-`, `ml-`, `mr-`, `text-left`, `text-right`). This is the first patient-facing surface in the app; it must be RTL-clean now so Phase 6's Hebrew switch requires no rework here.

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phases 1-2's scale:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (badge icon+text, slot chip internal spacing) |
| sm | 8px | Compact spacing: filter label-to-input gap, result-card internal element gaps |
| md | 16px | Default spacing: card internal padding, filter-field stacking, grid gap between result cards |
| lg | 24px | Page section padding, gap between filter panel and results grid, profile section spacing |
| xl | 32px | Gap between page header and content, gap between profile header and slot list |
| 2xl | 48px | Major section breaks (e.g. between profile details and upcoming-slots section) |
| 3xl | 64px | Page-level top spacing on wide viewports |

Exceptions:
- 44px minimum tap target for icon-only pagination controls (Prev/Next chevrons) — accessibility floor (WCAG 2.5.5/2.5.8), same exception class as Phase 2's row-action icon buttons, even though the visible button chrome (`Button` `icon`/`icon-sm` variants) renders smaller.
- Result cards and slot chips may render below 44px visual height individually, but the interactive element inside each (the "View profile" link, the disabled "Select this slot" control) must independently meet the 44px hit-area floor via padding, not by inflating the whole card.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 24px | 600 (semibold) | 1.2 |
| Display | 32px | 600 (semibold) | 1.2 |

Identical scale to Phases 1-2 — reused for cross-phase consistency, no new sizes introduced. Usage this phase:
- **Heading** = page titles ("Find a doctor" on `/search`, the doctor's `full_name` as the profile page's H1).
- **Label** = filter field labels, the "{N} doctors found" result-count caption next to pagination, upcoming-slot day-group headers ("Monday, August 10").
- **Body** = doctor card specialty/neighborhood/language text, profile bio, slot time chips, filter helper text.
- **Display** = not used this phase (no dashboard-style large stat numbers in search/profile UI) — kept declared only for cross-phase scale consistency; do not introduce a new use of it here.

Note: the "No upcoming availability" indicator (D-06) and the "Demo profile" badge both render at Badge-component internal sizing (`text-xs`, 12px, from `components/ui/badge.tsx`) — this is an inherited primitive token, not a new size added to this phase's scale.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` / `#ffffff` (`--background`) | Page background, result-card background, profile page background |
| Secondary (30%) | `oklch(0.97 0 0)` / `~#f7f7f7` (`--secondary` / `--muted`) | Filter panel background, non-active pagination page-number buttons, "No upcoming availability" badge fill (secondary badge variant), initials-avatar fill |
| Accent (10%) | `oklch(0.205 0 0)` / `~#1a1a1a` (`--primary`) | Reserved for: the "View profile" primary link/button on each result card, the current/active pagination page number, focus-visible rings on any focused control, and the selected state of a quick-select date shortcut chip (Today / Next 7 days / Next 30 days) |
| Destructive | `oklch(0.577 0.245 27.325)` / red (`--destructive`) | Text color only, for the "Could not load doctors" / "Doctor not found" error-state copy — matches Phase 2's precedent of using `text-destructive` for error messages. **No destructive user actions exist in this phase** (search and profile viewing are read-only per D-17) |

Accent reserved for: the "View profile" card action, the active pagination page number, focus rings, and the selected quick-select date chip — nothing else. Result cards, badges (specialty/language/neighborhood chips, "Demo profile" badge), and non-active pagination controls stay neutral (`secondary`/`outline` variants), continuing the project's grayscale-first, accent-is-not-decorative direction established in Phase 2.

| overflow | doctor-card (full_name) | ✅ covered | Doctor full name truncates with ellipsis at a fixed max card width (single line) rather than wrapping and destabilizing card height; the untruncated name is always shown in full on the profile page |

| long-text | select-slot-cta | ✅ covered (dismissed) | Button label is a fixed short string ("Select this slot") with no dynamic input — no wrapping/truncation risk |
