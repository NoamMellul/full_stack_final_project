<objective>
Give patients a public doctor profile page that shows everything they need to decide whether to book, plus a read-only list of upcoming available slots that is honest about not being bookable yet.

Purpose: search results answer "which doctors match my criteria"; the profile answers "is this the right doctor for me". It is also the surface where the demo nature of the data must be unmistakable (PROFILE-02) and where a control that will become the booking entry point in Phase 5 must be visibly inert today rather than silently doing nothing (D-18).

Output: `GET /api/doctors/[id]`, the `/doctors/[id]` page with all its render states, and the `doctor-profile` Playwright spec.
</objective>

    Guard the id shape first. Declare a module-level `const UUID_PATTERN = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;` and, when `id` does not match, return `NextResponse.json({ error: "Doctor not found." }, { status: 404 })` immediately.     Declare `const PUBLIC_DOCTOR_SELECT` as: `"id, full_name, bio, photo_url, is_demo, specialty:specialties(id,name_en,name_he), location:locations(id,city,neighborhood,address), languages:doctor_languages(languages(id,code))"`.     Query the doctor with `createClient()`, `.from("doctors").select(PUBLIC_DOCTOR_SELECT).eq("id", id).eq("is_active", true).maybeSingle()`. The `is_active` predicate is defense-in-depth restating the RLS policy, matching the convention documented in `app/api/admin/doctors/[id]/route.ts`. On a Supabase `error`, return the 500 body `{ error: "Could not load this doctor. Please try again." }`. On a null row, return the 404 body `{ error: "Doctor not found." }` — the same literal already used by the admin route and locked by the UI-SPEC as the profile page's error heading source.

    Query the slots with `.from("availability_slots").select("id, start_at, end_at").eq("doctor_id", id).eq("status", "available").gt("start_at", new Date().toISOString()).order("start_at", { ascending: true })`. The `status` and `start_at` predicates are defense-in-depth over `availability_slots_select_available_or_owner_or_admin`. On error, return the same 500 body.

    Flatten the languages embed with the same `flatMap` idiom as `toListRow` in the admin route, and respond with `NextResponse.json({ doctor: { ...flattened }, upcomingSlots: slots ?? [] })`.
