<objective>
Close the single gap `03-VERIFICATION.md` recorded for Phase 3: a `q` consisting entirely of LIKE/PostgREST metacharacters strips down to an empty string, is mapped to `q = null`, and therefore applies **no name filter at all** — so `GET /api/doctors?q=%25` returns the full 12-doctor directory, observably identical to searching for nothing. This contradicts the locked SEARCH-01/T-03-01 must-have that "a lone wildcard character cannot be used to match every row or to alter the predicate," and was independently flagged as WR-01 in `03-REVIEW.md`.

Purpose: the name filter currently **fails open**. The availability-range filter in the very same route already **fails closed** (an empty matching-id list short-circuits to an empty page rather than falling through unfiltered, T-03-13). This plan makes the name filter obey the same rule, so both filters in the endpoint share one invariant: a filter that cannot match anything returns nothing, never everything.

Output: a widened `ParsedSearchParams` carrying an explicit unmatchable-term discriminator, a fail-closed short circuit in `GET /api/doctors` mirroring the existing availability short circuit, and two regression tests — one at the API layer over all four metacharacters, one at the patient-visible `/search` layer — proven to fail against the current code before the fix lands.

**Scope guard.** This plan fixes exactly the one item in the `gaps:` block of `03-VERIFICATION.md`. It does not touch `03-REVIEW.md` WR-02 (fabricated `total: 0` on an out-of-range page) or WR-03 (no `.limit()` on the upcoming-slots query) — both are explicitly non-blocking warnings outside the `gaps:` block. It does not re-plan any of the six already-executed plans, whose `PLAN.md` and `SUMMARY.md` files remain the historical record of what shipped.
</objective>
