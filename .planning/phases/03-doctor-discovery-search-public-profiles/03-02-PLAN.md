    Add four new exports built on the same offset-resolution technique:
    - `jerusalemWallClockToUtc(year: number, month: number, day: number, hour: number, minute: number): Date` — builds `Date.UTC(year, month - 1, day, hour, minute, 0, 0)` as a naive instant, resolves `getTimeZoneOffsetMs(JERUSALEM_TIME_ZONE, guess)` at that instant, and returns `new Date(naiveUtc - offsetMs)`. `month` is 1-based to match `jerusalemBoundaryToUtcIso`'s input convention.     - `jerusalemWeekday(date: Date): number` — returns 0 for Sunday through 6 for Saturday, computed with `Intl.DateTimeFormat("en-US", { timeZone: JERUSALEM_TIME_ZONE, weekday: "short" })` mapped through a literal Sun/Mon/Tue/Wed/Thu/Fri/Sat lookup. Never use `Date.prototype.getDay()`, which reports the runner's local zone.
    - `jerusalemDayKey(iso: string): string` — returns the `YYYY-MM-DD` calendar day of an ISO instant in Asia/Jerusalem, assembled from `Intl.DateTimeFormat` parts with `year: "numeric", month: "2-digit", day: "2-digit"`. This is the grouping key the profile page uses to bucket slots by day.
    - `formatJerusalemDayHeading(iso: string): string` — returns a heading such as "Monday, August 10" via `Intl.DateTimeFormat("en-US", { timeZone: JERUSALEM_TIME_ZONE, weekday: "long", month: "long", day: "numeric" })`.
    - `formatJerusalemTime(iso: string): string` — returns a 24-hour "HH:MM" string via `Intl.DateTimeFormat("en-US", { timeZone: JERUSALEM_TIME_ZONE, hour: "2-digit", minute: "2-digit", hourCycle: "h23" })`.

    `seedAvailabilitySlots()` does the following, in order:

    1. Resolve the doctor set by READING BACK from the database, not from `seedDoctors()`'s return value: `select("id, full_name").eq("is_demo", true).in("full_name", DOCTORS.map(d => d.full_name)).order("full_name")`. This matters because `seedDoctors()` returns only newly inserted rows and returns an empty array on every re-run — keying off it would mean slots are only ever seeded on the very first run of a fresh database. Throw on error, using the same `throw new Error(...)` message style the file already uses.

    2. Drop the `DOCTORS_WITHOUT_SLOTS` names from that set (D-02).

    3. Idempotency check (D-03): `select("doctor_id").in("doctor_id", candidateIds).gt("start_at", new Date().toISOString())` against `availability_slots`, build a `Set` of the returned `doctor_id` values, and keep only candidates absent from that set. The filter is on FUTURE rows specifically — a doctor whose seeded slots have all expired should be re-seeded, and a doctor with any future slot must be skipped so the exclusion constraint is never challenged. Return early if nothing remains.

    4. Generate rows. For the doctor at index `i` in the remaining (name-sorted) list, choose three distinct day offsets from today: `1 + (i % 7)`, that plus 5, and that plus 11, each clamped so it never exceeds `HORIZON_DAYS`. For each offset, build the candidate calendar date by adding the offset to today's date, then advance it forward one day at a time while `jerusalemWeekday(candidate)` is 5 (Friday) or 6 (Saturday), so every slot lands on the Sunday-through-Thursday Israeli work week. If advancing pushes a date past `HORIZON_DAYS`, walk it backwards instead rather than exceeding the horizon. Deduplicate the three resolved dates in case the weekday skip collides two of them, replacing a collision with the next legal day.

       On each resolved date, the first slot starts at `WINDOW_START_HOUR` hours plus `(i % 6) * SLOT_MINUTES` minutes, and the following two slots each start `SLOT_MINUTES` later. Build `start_at` with `jerusalemWallClockToUtc(year, month, day, hour, minute)` and `end_at` as `start_at` plus `SLOT_MINUTES` minutes. Because same-day slots are consecutive fixed-length blocks and different days cannot intersect, the generated set for a doctor is non-overlapping by construction — the GiST constraint is the backstop, not the mechanism. Assert during generation that the last slot of a day ends no later than `WINDOW_END_HOUR`.

    5. Insert every generated row in one `insert` call with `status: "available"` set explicitly on each row rather than relying on the column default, and throw with the Postgres message on error. Create no `appointments` rows anywhere in this function (D-01, D-17).

    Finally, extend `printSummary()` to report the slot count by adding an `availability_slots` line, so a seed run visibly states how many slots exist. Keep the existing summary format style.

    Do not add any delete or truncate call to this script — it remains insert-only (T-02-16 from Phase 2 still holds).
