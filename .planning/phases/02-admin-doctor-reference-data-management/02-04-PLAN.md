<interface_contract>
- `GET /api/admin/users` → 200 `{ users: { id, role, full_name, email, created_at }[] }`
- `GET /api/admin/appointments?status=&doctorId=&from=&to=` → 200 `{ appointments: AppointmentRow[] }`
  where `AppointmentRow` is
  `{ id, status, cancelled_reason, created_at, updated_at, slot: { id, start_at, end_at, status }, doctor: { id, full_name }, patient: { id, full_name, email } }`

Query params are all optional and combine with AND semantics. `status` matches
`appointments.status` exactly. `doctorId` matches `appointments.doctor_id`. `from` and `to` are
ISO-8601 UTC instants filtering on the joined slot's `start_at` via an inner embed
(`availability_slots!inner(...)` plus `.gte`/`.lte` on `availability_slots.start_at`).

Both endpoints order on parent-table columns only — `created_at` descending then `id` descending —
so ordering never depends on PostgREST embedded-resource ordering behaviour. Times are stored and
returned as UTC `timestamptz`; the `Asia/Jerusalem` conversion happens only at render time, per the
project timezone constraint.

Both routes export `GET` and nothing else. They are read-only by contract.
</interface_contract>
