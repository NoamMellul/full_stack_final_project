<interface_contract>
Other plans in this phase build against these exact signatures. Do not deviate.

`lib/auth/require-admin.ts`:
```
export type AdminGuardResult =
  | { ok: true; supabase: Awaited<ReturnType<typeof createClient>>; userId: string }
  | { ok: false; response: NextResponse };

export async function requireAdmin(): Promise<AdminGuardResult>;
```
Unauthenticated → `{ ok: false, response: 401 { error: "Not authenticated." } }`.
Authenticated with `profiles.role !== "admin"` → `{ ok: false, response: 403 { error: "Not authorized." } }`.

`lib/validation/doctor.ts`:
```
export function validateDoctorInput(body: Record<string, unknown>): string | null;
```

`app/api/admin/doctors/route.ts` response shapes:
- `GET` → 200 `{ doctors: DoctorListRow[] }` where each row is
  `{ id, full_name, bio, photo_url, is_active, is_demo, profile_id, created_at, specialty: { id, name_en, name_he }, location: { id, city, neighborhood }, languages: { id, code }[] }`
- `POST` → 201 `{ doctor: DoctorListRow }`; validation failure → 400 `{ error: string }`

**Next.js 16 note (applies to every `[id]` route in this phase):** dynamic route params are a
Promise. The handler signature is
`(request: Request, { params }: { params: Promise<{ id: string }> })` and the id is read with
`const { id } = await params;`. The example in 02-RESEARCH.md Pattern 2 uses the pre-Next-15
synchronous shape and must not be copied verbatim on that point.
</interface_contract>
