# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase surface (per objective):** Admin CRUD interface — `/admin` dashboard, `/admin/doctors` (list + create/edit form + activate/deactivate + link-account flow), `/admin/specialties` and `/admin/locations` (list + create/edit/delete-with-guard), `/admin/users` and `/admin/appointments` (read-only oversight lists) — plus the doctor-side forced `/doctor/change-password` page triggered by `must_change_password`. No patient-facing UI in this phase.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized in Phase 1 — `components.json` present, do not re-init) |
| Preset | `base-nova` style, `neutral` base color, `cssVariables: true`, `rtl: true` — unchanged from Phase 1, reused for design-system continuity across phases |
| Component library | Base UI (`@base-ui/react`) — **not** Radix, confirmed by `components/ui/button.tsx` |
| Icon library | `lucide-react` (already installed) |
| Font | Geist Sans (UI text) / Geist Mono, via `next/font/google` in `app/layout.tsx` — the Phase 1 `--font-sans` variable-naming bug is already fixed (`app/layout.tsx:6` maps `variable: "--font-sans"` directly), no action needed this phase |

**New primitives required this phase (not yet installed):** `dialog`, `table`, `select`, `textarea`, `switch`, `badge`, `skeleton` — install via:
```bash
npx shadcn add dialog table select textarea switch badge skeleton
```
Already-installed primitives to reuse as-is: `button`, `card`, `input`, `label`, `alert`.

**No shadcn `Form` wrapper this phase** (same as Phase 1): shadcn's `Form` assumes `react-hook-form`. Per the project's no-Zod/no-schema-library convention, use plain primitives (`Input`, `Label`, `Select`, `Textarea`, `Switch`, `Button`, `Card`, `Dialog`, `Alert`) with manual React state and the manual validation functions in `lib/validation/doctor.ts` / `lib/validation/reference-data.ts` (per `02-RESEARCH.md`).

**RTL note:** `rtl: true` remains active. All new layout/spacing classes (tables, forms, dialogs, toolbars) must use logical properties (`ps-`, `pe-`, `ms-`, `me-`, `text-start`, `text-end`) — never physical (`pl-`, `pr-`, `ml-`, `mr-`, `text-left`, `text-right`). This matters more this phase than Phase 1: table columns, row-action icon buttons, and dialog close buttons all have a directional side that must mirror correctly once Phase 6 ships RTL switching.

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 1's scale, extended with table-specific usage:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (row action icons, badge icon+text) |
| sm | 8px | Compact spacing: label-to-input gap, inline error text gap, table cell vertical padding |
| md | 16px | Default spacing: form field stacking, card internal padding, table cell horizontal padding |
| lg | 24px | Page section padding, dialog content padding, toolbar-to-table gap |
| xl | 32px | Gap between page header and content, dashboard summary-card grid gap |
| 2xl | 48px | Major section breaks (e.g. between dashboard summary and a future activity feed) |
| 3xl | 64px | Page-level top spacing on wide viewports |

Exceptions:
- 44px minimum tap target for icon-only row actions in tables (edit, link-account, activate/deactivate toggle) — accessibility floor (WCAG 2.5.5/2.5.8), same exception class as Phase 1's header logout button.
- Table rows themselves may render below 44px visual height (dense list convention), but the interactive controls inside each row (icon buttons, switch) must independently meet the 44px hit-area floor via padding, not by inflating row height.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 24px | 600 (semibold) | 1.2 |
| Display | 32px | 600 (semibold) | 1.2 |

Identical scale to Phase 1 — reused for cross-phase consistency, no new sizes introduced. Usage this phase:
- **Display** = dashboard summary card numbers (doctor count, active-doctor count, user count, appointment count).
- **Heading** = page titles ("Doctors", "Specialties", "Locations", "Users", "Appointments", "Admin dashboard").
- **Label** = table column headers, form field labels, dashboard summary card captions ("Doctors", "Active doctors", "Registered users", "Appointments").
- **Body** = table cell content, form helper text, dialog body copy.

Note: inline error/guard text (field validation, delete-guard explanation "used by N doctors") uses **Label size (14px)** at **regular weight (400)**, same rule as Phase 1 — semibold stays reserved for actual field labels and column headers, never for error/guard text, keeping the two visually distinct.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` / `#ffffff` (`--background`) | Page background, card/dialog background, table background |
| Secondary (30%) | `oklch(0.97 0 0)` / `~#f7f7f7` (`--secondary` / `--muted`) | Table header row background, toolbar background, dashboard summary card background, table row hover state |
| Accent (10%) | `oklch(0.205 0 0)` / `~#1a1a1a` (`--primary`) | Reserved for: primary submit/create buttons ("Add doctor", "Save doctor", "Add specialty", "Add location", "Generate temporary password", "Update password"), the focus ring (`--ring`) on any focused control, and the "Active" status badge fill |
| Destructive | `oklch(0.577 0.245 27.325)` / red (`--destructive`) | Reserved for: the enabled "Delete" button on specialties/locations, its confirm-dialog "Delete" button, and all form/API error messages (validation errors, save/fetch failures) |

Accent reserved for: the six primary action buttons listed above, focus-visible rings, and the "Active" doctor-status badge fill. Nothing else uses accent — table rows, icon-only row actions (edit, link-account), secondary buttons ("Cancel", "Deactivate"), and the "Inactive"/"Demo" badges stay neutral (`outline`/`secondary` button and badge variants), continuing Phase 1's explicit "grayscale-first, accent is not decorative" direction. Deactivating a doctor is reversible and therefore uses a neutral `secondary`/`outline` button, never destructive styling — destructive red is reserved strictly for the one truly irreversible action this phase exposes (deleting a specialty/location once no doctor references it).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | doctors-table, specialties-table, locations-table, users-table, appointments-table | ✅ covered | Each renders the documented empty-state heading/body from the Copywriting Contract in place of the table; appointments-table's empty state is expected to be the only state exercised throughout Phase 2 (no booking flow exists until Phase 5) |
| empty | doctor-form, specialty-form, location-form, link-account-form, change-password-form | ✅ covered | Unfilled inputs show placeholder/label only; submit stays enabled but client-side presence checks block submission and surface the per-field "required" copy before any network call, matching Phase 1's signup/login pattern |
| loading | doctors-table, specialties-table, locations-table, users-table, appointments-table | ✅ covered | Each table renders 3 skeleton placeholder rows (`Skeleton` primitive) during the initial `GET`, replaced by real rows or the empty state on completion |
| loading | doctor-form, specialty-form, location-form, link-account-form, change-password-form | ✅ covered | Submit button disables and its label swaps to an in-progress verb ("Saving…", "Linking…", "Updating…") for the duration of the request, preventing double-submit |
| loading | activate-toggle | ✅ covered | Switch disables itself during its own PATCH request; re-enables on response (success or error) |
| error | doctor-form, specialty-form, location-form, link-account-form, change-password-form | ✅ covered | Inline field errors + save-failure banner render per the Copywriting Contract, destructive color, Label size/regular weight |
| error | doctors-table, specialties-table, locations-table, users-table, appointments-table | ✅ covered | Fetch failure replaces the table body with the documented "Could not load…" message and a "Retry" link/button |
| error | delete-guard-control | ✅ covered | Disabled-button inline explanation (D-05 copy) covers the client-side path; the D-06 server-side rejection copy covers the bypass path (dev-tools direct DELETE call) |
| populated | doctors-table, specialties-table, locations-table, users-table | ✅ covered | Typical demo volume (10-15 doctors, ~20-30 combined specialties/locations, a handful of users) renders as a plain scrollable table, no pagination needed at this scale — see overflow row below for the volume ceiling this assumption holds to |
| populated | appointments-table | ✅ covered (dismissed) | No appointment rows can exist until Phase 5 ships booking — the populated layout for this table is explicitly out of scope for Phase 2 and will be verified when Phase 5 lands real data, not before |
| zero-one-many | doctors-table, specialties-table, locations-table, users-table | ✅ covered | Each list page shows a count caption ("{N} doctors" / "{N} specialties" / "{N} locations" / "{N} users"), using the plural form for 0 and 2+ and singular for exactly 1 (e.g. "1 doctor") |
| partial | doctors-table | ✅ covered | A doctor created but not yet linked to a login account (`profile_id` null) renders with a neutral "Not linked" badge in place of a status error — this is an expected, valid intermediate state, not a failure |
| partial | doctor-form, specialty-form, location-form | 🧪 backstop | On submit with only some fields invalid, only the offending field(s) show inline errors; already-valid fields retain their entered values (no full-form reset) — verify visually |
| overflow | doctors-table, specialties-table, locations-table, users-table, appointments-table | 🧪 backstop | Long full-name/bio/email/specialty-name values truncate with ellipsis within a fixed-width table cell rather than expanding the row or breaking the layout — verify visually |
| overflow | admin-dashboard-summary | 🧪 backstop | The 4 summary cards wrap to a 2x2 grid below the `md` breakpoint rather than horizontally scrolling — verify visually |
| long-text | doctor-form (bio field) | ✅ covered | Bio is a multi-line `Textarea` with no character limit enforced this phase; it wraps naturally and grows the field, never truncates while typing |
| long-text | delete-guard-control | ✅ covered | The inline guard sentence is a fixed short template with only a numeric substitution ("used by {N} doctors") — no long-text risk |
| long-text | admin-dashboard-summary | ✅ covered | Card captions are fixed, short strings ("Doctors", "Active doctors", "Registered users", "Appointments") — no dynamic long-text risk |
| long-text | doctors-table, users-table | 🧪 backstop | Long doctor full-name / user email values truncate with ellipsis at a fixed max column width rather than wrapping to a second row — verify visually (same mechanism as the overflow row above, called out separately since it is the long-text-specific instance of it) |
