<interface_contract>
`lib/validation/doctor.ts` gains:
```
export function validateDoctorPatch(body: Record<string, unknown>): string | null;
export function validateStatusInput(body: Record<string, unknown>): string | null;
```
`validateDoctorPatch` validates only the keys actually present (a partial update), reusing the
same message strings as `validateDoctorInput`, and rejects a body with no editable key at all
with "Nothing to update.".
`validateStatusInput` requires `isActive` to be a real boolean → "Status must be true or false.".

Endpoints (both take `{ params }: { params: Promise<{ id: string }> }` — Next.js 16 makes route
params a Promise; read the id with `const { id } = await params;`):
- `PATCH /api/admin/doctors/[id]` body `{ fullName?, specialtyId?, locationId?, bio?, photoUrl?, languageIds? }`
  → 200 `{ doctor: DoctorListRow }` · 400 `{ error }` · 404 `{ error: "Doctor not found." }`
- `PATCH /api/admin/doctors/[id]/status` body `{ isActive: boolean }`
  → 200 `{ doctor: DoctorListRow }` · 400 `{ error }` · 404 `{ error: "Doctor not found." }`

`DoctorListRow` is the shape defined in plan 02-01's `<interface_contract>` and returned by
`GET /api/admin/doctors`.
</interface_contract>
