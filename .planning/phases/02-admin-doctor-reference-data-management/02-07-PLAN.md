<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any visitor → `/admin/*` pages | The request gate handles auth-presence; the admin layout handles role |
| any HTTP client → `/api/admin/*` | The request gate does not match this prefix, so the route-handler guard and RLS are the only defences |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02 | Elevation of Privilege | every `/api/admin/*` endpoint reached directly, bypassing the browser entirely | high | mitigate | `requireAdmin()` in every handler plus the `*_admin_write` and `*_select_own_or_admin` RLS policies as an independent second layer; Task 2 asserts 401/403 across the whole endpoint matrix and confirms no write occurred |
| T-02-18 | Elevation of Privilege | a patient or doctor reaching an admin page because the request gate defers role checks | high | mitigate | `app/admin/layout.tsx` performs the role check for the whole subtree, unchanged from Phase 1; Task 2 asserts it for all six pages against both non-admin roles |
| T-02-19 | Information Disclosure | dashboard counts leaking platform-wide totals to a non-admin | medium | mitigate | The dashboard is a Server Component behind the layout guard, and its count queries run through the session client so RLS would return zero rows to a non-admin even if the guard were bypassed |
</threat_model>
