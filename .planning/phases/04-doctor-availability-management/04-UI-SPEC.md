# Phase 04 — UI Design Contract

> Visual and interaction contract for `/doctor/schedule` (Doctor Availability Management). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase adds ONE new page (`app/doctor/(gated)/schedule/page.tsx`) and no new visual system — it is a pure extension of the design language already shipped in Phase 2 (admin CRUD dialogs, delete-confirmation pattern) and Phase 3 (day-grouped slot list, Asia/Jerusalem formatting helpers). This contract locks how those existing patterns compose for the new doctor-only entities (`available` slot, `blocked` period), not a new design system.

## Spacing Scale

Declared values (must be multiples of 4), matching every prior phase's usage:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside a badge |
| sm | 8px | Compact stacked spacing (badge + reason line, form field label-to-input) |
| md | 16px | Default element spacing (form field-to-field, card padding) |
| lg | 24px | Section padding, gap between the header row and the list |
| xl | 32px | Layout gaps (not expected to be needed on this single-column page) |
| 2xl | 48px | Major section breaks (not expected on this page) |
| 3xl | 64px | Page-level spacing (not expected on this page) |

Exceptions (both already established elsewhere in the codebase — reused, not invented):
- **12px (`gap-3`)** — compact horizontal pairing of a time range and its action button/badge on one row (matches `app/doctors/[id]/page.tsx`'s existing slot-row `gap-3`).
- **44px (`min-h-11`) minimum touch target** — the Delete button on each schedule row must be at least 44px tall on touch/mobile, matching the existing `min-h-11` convention already used for the (currently inert) "Select this slot" button on the public profile page.

## Color

Neutral (grayscale) shadcn theme — no brand hue exists in this project's tokens; "accent" below means the primary near-black token, not a colored highlight.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` white) | Page background |
| Secondary (30%) | `--secondary` / `--muted` (`oklch(0.97 0 0)` light gray) | Cards, the "Blocked" status badge, muted/help text, skeleton rows |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)` near-black) | Reserved for: the "Add slot" submit button, the "Available" status badge (`variant="default"`), and focus rings |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)` red) | Reserved for: the "Delete" action on any row, the destructive confirmation dialog's confirm button, and every server-rejected-write error message (past-date, overlap, booked-slot-delete) |

Accent reserved for: **only** the "Add slot" primary submit button and the "Available" badge variant. The "Block period" submit button uses `variant="outline"` (secondary tier, not accent) — it is an equally required action (AVAIL-06) but visually secondary to the more frequent "Add slot" action, keeping the 10% accent budget from being spent on two equal-weight buttons. Table/list row action icons (edit-style pencil, if ever added) would use `variant="ghost"`, matching Phase 2's reference-data table precedent — not applicable here since this phase has no edit action, only add/delete/block.

## Layout — Add slot / Block period forms (Claude's Discretion in CONTEXT.md, locked here for consistency)

**Decision: two separate `Dialog` triggers**, not inline always-visible forms and not a tab switch (no Tabs primitive exists in this repo — confirmed absent).

- Page header row: `<h1>My schedule</h1>` (Display role) on the left; `Add slot` (`variant="default"`) and `Block period` (`variant="outline"`) buttons on the right, `gap-2` between them — directly mirrors `components/admin/reference-data-page-client.tsx`'s `Add {item}` trigger-button pattern.
- Each button opens its own `Dialog` with a `DialogHeader`/`DialogTitle` ("Add a slot" / "Block a period"), a `flex flex-col gap-4` form body, an inline `Alert variant="destructive"` for submit errors, and a `DialogFooter` with a single submit button whose label swaps to an in-flight state ("Adding…" / "Blocking…") — the exact shape already shipped for the create-dialog in `reference-data-page-client.tsx`.
- Add-slot form fields: date, start time, end time (three inputs, `type="date"` + two `type="time"`, converted via `jerusalemWallClockToUtc` on submit).
- Block-period form fields: start date, start time, end date, end time, optional `reason` (`Textarea`, no character limit per D-04's "no validation on content").
- Below the header row: the day-grouped schedule list (see Schedule List below).

## Layout — Schedule list (D-13)

Day-grouped list, not a calendar grid — direct adaptation of `app/doctors/[id]/page.tsx`'s `groupSlotsByJerusalemDay` pattern, carrying `status` and `reason` per row instead of the public page's available-only shape.

- Per-day heading: `formatJerusalemDayHeading()` output (e.g. "Monday, August 17"), Label role (14px/600).
- Per-row format: `{formatJerusalemTime(start)} – {formatJerusalemTime(end)}` followed by a status `Badge` — `variant="default"` + text "Available" for available rows, `variant="secondary"` + text "Blocked" for blocked rows — followed by the optional reason as plain muted text when present ("Blocked — Vacation"), followed by a `Delete` button (`variant="destructive"`, `size="sm"`, `min-h-11` touch target) that opens the matching confirm dialog from the Copywriting Contract above.
- `booked` rows: same row format, status badge `variant="outline"` + text "Booked", **no Delete button rendered at all** (not disabled-and-visible — matching the Phase 3 precedent of omitting rather than disabling an inert control, per PROJECT.md D-06 in `app/doctors/[id]/page.tsx`'s empty-slots handling) — satisfies AVAIL-05 at the UI layer (the real guarantee is server-side per D-01/RESEARCH.md).
- List scope: future (today-and-forward) entries only, per D-15 — no date-range picker, no pagination (demo data volume).
