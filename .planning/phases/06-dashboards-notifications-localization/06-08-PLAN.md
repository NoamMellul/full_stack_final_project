| Boundary | Description |
|----------|-------------|
| dictionary value → rendered DOM on public pages | These are the pages an unauthenticated visitor reaches, so any injection surface here is reachable without a session |
| validator message → translated form error | A message string is used as a lookup identifier at the render boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-36 | Tampering | XSS through a translated string on a public page | medium | mitigate | Every `t()` result is rendered as a React child; no `dangerouslySetInnerHTML` is introduced, and dictionary values are repo-authored, never user-supplied |
| T-06-37 | Information Disclosure | login error copy becoming a user-enumeration oracle | high | mitigate | The login route's deliberately identical 400 and 401 messages are server-authored and unchanged by this plan; the client renders whatever the route returns, and no branch-specific copy is introduced |
| T-06-38 | Tampering | a retrofit silently changing a rendered English string | medium | mitigate | The existing Phase 1-5 specs are the regression detector and may not be edited; a red spec means the retrofit is wrong |
| T-06-39 | Information Disclosure | search input sanitisation regressing during the retrofit | high | mitigate | No change is permitted to `parseSearchParams`, the URL-writing behaviour, or any query parameter handling — only rendered copy changes, so the Phase 3 metacharacter-stripping guarantee is untouched |
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install occurs in this plan |
