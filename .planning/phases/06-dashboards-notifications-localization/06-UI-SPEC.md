# Phase 06 — UI Design Contract

> Visual and interaction contract for the patient dashboard, doctor dashboard, favorites (two toggle
> entry points + the `/patient/favorites` list), the shared notification bell/dropdown, and the
> global language switcher + RTL mirroring (Dashboards, Notifications & Localization). Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase adds no new visual system. It extends the exact design language already
shipped in Phases 2-5 (`app/admin/page.tsx`'s stat-card pattern, `app/doctors/[id]/page.tsx`'s
day-grouped slot list, `components/logout-button.tsx`'s responsive icon-button touch target, Phase 5's
Dialog/status-region conventions). This is also the **first phase where `dir="rtl"` is actually
exercised at runtime** — every layout decision below is written with the RTL mirroring contract as a
first-class constraint, not an afterthought.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present, no gate action needed) |
| Preset | `style: base-nova`, `baseColor: neutral`, `cssVariables: true`, `rtl: true` [VERIFIED: components.json] |
| Component library | Base UI (`@base-ui/react`) — confirmed via existing `components/ui/*` imports, not Radix |
| Icon library | lucide-react [VERIFIED: components.json `iconLibrary`] |
| Font | Geist Sans (`--font-sans`, via `next/font/google`, **Latin subset only**), Geist Mono for `--font-mono` [VERIFIED: app/layout.tsx, app/globals.css] |

**New component to generate this phase:** `components/ui/popover.tsx` via `npx shadcn add popover`.
`@base-ui/react/popover` is already bundled in `node_modules` (no new npm dependency) but no wrapper
file has been generated yet [VERIFIED via RESEARCH.md Pitfall 5: `ls components/ui/` this session
listed only `alert, badge, button, card, dialog, input, label, select, skeleton, switch, table,
textarea`]. **Decision:** the notification bell uses a `Popover` (anchored, lightweight dropdown), not
a `Dialog` (full modal overlay) — a bell's unread list is a transient, dismiss-on-outside-click
affordance, not a page-blocking interaction; a `Dialog` would be the wrong weight for it. This is the
one net-new UI primitive this phase adds.

No other new shadcn components needed. Reused primitives: `card`, `badge`, `button`, `skeleton`,
`alert` (all already installed).

**Font/RTL flag (assumption, not a locked guarantee):** Geist Sans is Latin-only — it has no native
Hebrew glyphs. Standard browser glyph-fallback behavior will transparently substitute the OS's default
sans-serif font (e.g. Segoe UI / Arial / Noto Sans Hebrew) for Hebrew characters even though only
`--font-sans` (Geist + its metrics-matched Latin fallback) is declared in the CSS font stack. This
means Hebrew text will render in a visually different typeface than the English UI — an accepted
tradeoff for this project's scope, not a defect to fix by adding a Hebrew webfont (out-of-scope new
dependency). Flagged for awareness; no action required unless visual QA during Hebrew testing shows an
actually broken (tofu/missing-glyph) render rather than just a different-but-legible typeface.

## Spacing Scale

Declared values (must be multiples of 4), unchanged from every prior phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside a badge, unread-dot-to-message-text gap in the notification list |
| sm | 8px | Compact stacked spacing (stat-card value-to-caption gap, language-switcher button gap) |
| md | 16px | Default element spacing (dashboard card internal gap, favorites-list row gap) |
| lg | 24px | Section padding, gap between dashboard "summary" and "quick links" blocks |
| xl | 32px | Gap between page header and first section on `/patient/dashboard` / `/doctor/dashboard` / `/patient/favorites`, matching `app/admin/page.tsx`'s existing `mt-8` |
| 2xl | 48px | Major section breaks (not expected at typical demo-data volume) |
| 3xl | 64px | Page-level spacing (not expected at typical demo-data volume) |

Exceptions (all reused/established, not invented):
- **12px (`gap-3`)** — compact horizontal pairing inside a notification row (dot/text/timestamp) and
  inside a favorites-list row, matching the existing slot-row `gap-3` precedent.
- **32px stat-card number (`text-[32px]`)** — the doctor dashboard's two count cards reuse
  `app/admin/page.tsx`'s exact existing stat-card treatment verbatim (see Typography), not a new
  pattern.
- **Responsive icon-button touch target, `size-11 sm:size-8`** — every icon-only control this phase
  adds (favorite-toggle heart, notification-bell trigger, each language-switcher button) follows
  `components/logout-button.tsx`'s exact existing responsive pattern: 44px square on mobile (real touch
  target), collapsing to the Button primitive's `icon` size (32px, `size-8`) at `sm:` and above,
  matching every other icon control already in the header. Do not introduce a different breakpoint or
  a flat 44px-everywhere rule — mirror this established precedent exactly.

## Color

Neutral (grayscale) shadcn theme — no brand hue exists in this project's tokens; identical palette to
every prior phase. This phase introduces **zero new semantic colors** — it reuses exactly the same two
(`--primary` accent, `--destructive`) already governed by Phase 5's discipline.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` white) | Page background |
| Secondary (30%) | `--secondary` / `--muted` (`oklch(0.97 0 0)` light gray) | Dashboard/favorites cards (`bg-secondary`, matching `app/admin/page.tsx`'s stat cards), popover body, skeleton rows |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)` near-black) | Reserved for: the **filled** favorite heart icon (favorited state, both entry points), the notification unread indicator dot and unread-count badge on the bell, the doctor dashboard's single "Manage my schedule" CTA, and each dashboard/favorites page's single empty-state CTA ("Find a doctor") |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)` red) | **Unchanged from Phase 5 — reserved for appointment-cancellation actions only.** This phase introduces no new destructive actions: removing a favorite is a low-stakes, instantly-reversible toggle (the same heart click, un-filled), so it is **not** styled destructive — using red for it would dilute red's established "irreversible-ish, needs a confirm" meaning from Phase 5 |

Accent discipline: **exactly one prominent (`default`-variant) action per screen**, continuing Phase
4/5's rule. Concretely:
- `/patient/dashboard`: no `default`-variant button when upcoming appointments exist (quick-link
  buttons are all `outline`); the *only* place `default` appears is the empty-state "Find a doctor" CTA
  (shown only when there are zero upcoming appointments).
- `/doctor/dashboard`: "Manage my schedule" is the one `default` button; "My appointments" stays
  `outline` (reused verbatim from the existing placeholder's already-correct split).
- Language-switcher active state uses `variant="secondary"` (subtle, non-competing highlight), **not**
  `default` — it must never contend with a page's real primary CTA for the accent budget.
- The notification-bell unread badge uses `--primary` fill (a small solid dot/pill), not `--destructive`
  red, per the reservation table above — this is a deliberate, explicit deviation from the extremely
  common "red badge for unread count" web convention, made to preserve this project's strict
  two-semantic-color discipline (red means "destructive action," nothing else, in this codebase).

## Layout — Header architecture change (D-06, prerequisite for everything below)

**This must happen before the language switcher or notification bell can appear on public pages.**
`SiteHeader` is currently mounted **only** inside the three role-scoped layouts
(`app/patient/layout.tsx`, `app/doctor/layout.tsx`, `app/admin/layout.tsx`) — it is **not** mounted
anywhere on `/`, `/search`, `/doctors/[id]`, `/login`, or `/signup` today [VERIFIED: `grep -rln
"SiteHeader" app/` returned only the three role-scoped layouts this session]. D-06's "always rendered,
including for logged-out visitors" only has effect once `SiteHeader` is actually present on those
public routes.

**Required change:** move `<SiteHeader />` into `app/layout.tsx` (the root layout, above
`{children}`), so it wraps **every** route — public and role-scoped alike — with one instance. Remove
the now-duplicate `<SiteHeader />` calls from `app/patient/layout.tsx`, `app/doctor/layout.tsx`, and
`app/admin/layout.tsx` (they keep their own auth/role redirect logic, just stop separately rendering
the header). `app/layout.tsx` already becomes dynamically-rendered app-wide once it reads the locale
cookie (RESEARCH.md Pitfall 3) — mounting `SiteHeader` (which itself calls `supabase.auth.getUser()`)
in the same tree does not add a *new* dynamic-rendering cost beyond what D-05 already requires.

**Resulting `SiteHeader` states:**
- **Logged out** (including anonymous visitors on `/search`, `/doctors/[id]`, `/login`, `/signup`,
  `/`): logo ("MedRDV") + language switcher only. No notification bell, no name, no logout button.
- **Logged in — patient or doctor:** logo + language switcher + notification bell + name + logout
  button (existing).
- **Logged in — admin:** logo + language switcher + name + logout button. **No notification bell** —
  `notifications.user_id` is only ever written for patients/doctors (Pattern 2), so an admin session
  has structurally nothing to show; omit the bell entirely for the admin role rather than rendering it
  disabled or perpetually empty (matches the established "omit, don't disable an inert control"
  convention from Phase 3).

## Layout — Favorite toggle (D-01)

**Focal point:** the heart icon button, identical visual contract at both entry points.

A single shared `FavoriteToggle` component, rendered in exactly two places:
1. `components/search/doctor-card.tsx` — absolute-positioned at the card's top **inline-end** corner
   (`className="absolute top-2 end-2"` — logical `end-2`, never `right-2`; the `Card` wrapper gains
   `relative` so this positions correctly in both LTR and RTL), overlaying nothing else in the card's
   existing layout.
2. `app/doctors/[id]/page.tsx` — inline, immediately after the `<h1>{doctor.full_name}</h1>` /
   "Demo profile" badge row (same row, not a new row).

**Visual states:**
- **Unfavorited:** outline-only `Heart` (lucide) icon, `text-muted-foreground` stroke, no fill.
  `variant="ghost"`, `size-11 sm:size-8` (Spacing Scale exception).
- **Favorited:** filled `Heart` icon (`className="fill-current"`), `text-primary` (accent color,
  reserved-for list above).
- **Toggling (optimistic, in flight):** icon flips immediately on click (optimistic update) before the
  API call resolves; button disables for the duration to prevent a double-click race.
- **Failed:** icon reverts to its pre-click state; the Copywriting Contract's failure message appears
  as a transient `role="status" aria-live="polite"` line near the toggle (same pattern Phase 2/4 use
  for inline confirmations).

**Role-gating (mirrors Phase 3's established "omit, don't disable" convention):** the toggle renders
for anonymous visitors and for authenticated **patient**-role sessions. It is **omitted entirely**
(not rendered, not disabled) when the viewer is authenticated as a doctor or admin — favoriting is a
patient-only concept, and there is no meaningful disabled-state affordance to show a doctor/admin here.

**Auth-on-click, not auth-on-mount (mirrors the booking CTA's established D-04 pattern from Phase
3/5):** clicking the heart as an anonymous visitor does **not** attempt the API call — it redirects
immediately to `/login?from=<current path>` via the existing browser Supabase client's cheap
`auth.getUser()` check. No toggle state ever renders "as if favorited" for a logged-out click.

**Cross-entry-point consistency (D-01's core requirement):** each page that renders a `FavoriteToggle`
independently fetches the current patient's full favorited-doctor-id set **once per page load** (not
per-card) — the search-results page and the doctor-profile page each call `GET
/api/patient/favorites` once and pass the resulting `isFavorited` boolean down as a prop to every
toggle instance on that page. This satisfies D-01's "reflected... on next render" wording without
requiring cross-tab/cross-page live sync — favoriting on `/doctors/[id]` and then navigating to
`/search` shows the correct filled state because `/search` re-fetches on its own mount, not because of
any shared client-side store.

## Layout — Notification bell + dropdown (D-02, D-03, NOTIF-01–04)

**Focal point:** the bell trigger's unread badge — the one element on every page that must reflect
live state without a reload.

**Trigger:** `Button variant="ghost" size-11 sm:size-8`, `Bell` (lucide) icon, positioned in
`SiteHeader`'s logged-in-only control group (between the user's name and the logout button). When
`unreadCount > 0`, a small solid `--primary`-filled circular badge overlays the icon's inline-end
corner (`className="absolute -top-1 end-1"` on a wrapping `relative` span — logical `end-1`, never
`right-1`), showing the count up to 9, then **"9+"** for 10 or more (this is the phase's one
overflow/long-text case on a fixed-size dot — the badge does not grow to fit 3-digit counts, it caps
at the 2-character "9+" glyph).

**Dropdown (`Popover`, `align="end" side="bottom"`, `w-80`):**
- Header: "Notifications" (Heading role).
- Body: `max-h-96 overflow-y-auto` (natural scroll, no fixed-height clipping beyond that cap — this
  is the dropdown's overflow-state coverage).
- **Loading (rare, only if the popover is opened before the mount-time `GET /api/notifications` first
  resolves):** 2 `Skeleton` rows.
- **Error:** Copywriting Contract's load-error line + `outline` Retry, inside the popover body.
- **Empty:** single centered "No notifications yet." line (Copywriting Contract), no separate CTA —
  there is nothing actionable to point the user toward from an empty notification feed.
- **Populated:** rows most-recent-first (already the API's `.order("created_at", {ascending: false})`).
  Each row: an inline-start unread dot (`--primary`, 8px circle, only when unread) + message text
  (resolved via Pattern 2's `notificationDictionaryKey(type, viewerRole)` — **never** the stored
  `message` column, per D-03) at Label role (600) if unread / Body role (400) if read, then a
  timestamp line beneath using `formatJerusalemDayHeading` + `formatJerusalemTime` (no invented
  relative-time formatting — reuse `lib/timezone.ts` as-is).

**Mark-as-read interaction (resolves RESEARCH.md's discretion point — locked, not left open):**
**opening the dropdown marks every currently-listed unread notification as read**, fired as
non-blocking `PATCH /api/notifications/[id]/read` calls per unread id the moment the popover opens (no
explicit per-item "mark read" click target, no separate "mark all as read" button). This is the
simpler of the two options RESEARCH flagged, matches this app's small-scale demo context, and avoids a
second interaction affordance for a requirement set (NOTIF-01–04) that only asks that a notification be
received and visible — not that read/unread be individually manageable. Visually: rows already marked
read on a *previous* open render without the dot/without Label-weight on the *next* open; a
notification that arrives live via Realtime while the dropdown is already open still renders unread
(dot + Label weight) until the dropdown is closed and reopened.

**Realtime update (D-02):** a live `postgres_changes` INSERT event appends the new row to the popover's
in-memory list (if open) and increments the trigger badge count — no toast, no sound, matching this
phase's scope (nothing in NOTIF-01–04 requires an interruptive alert, only that the badge/list reflect
new activity without a page refresh).

## Layout — Language switcher (D-05, D-06, I18N-01)

**Focal point:** always-visible, both logged-in and logged-out (Header architecture section above).

Two adjacent buttons in `SiteHeader` (`flex items-center gap-1`), `size="sm"`, labeled "EN" / "עב"
(Copywriting Contract — never translated). Active locale: `variant="secondary"`. Inactive locale:
`variant="ghost"`. Clicking the inactive one: `POST /api/locale` (Route Handler, cookie write per
D-05/RESEARCH Pattern 4) → `router.refresh()`. The clicked button disables for the brief duration of
that round trip (no separate loading-copy needed — the whole page's server-rendered content updates
via `refresh()`, which is the visible feedback).

**RTL mirroring contract (I18N-02) — applies to every element in this document, not just this
component:**
- Only Tailwind **logical-property** utilities: `ps-`, `pe-`, `ms-`, `me-`, `text-start`, `text-end`,
  and — newly relevant this phase for the absolute-positioned heart/badge overlays — `start-*`/`end-*`
  for inset positioning. **Never** `pl-`, `pr-`, `ml-`, `mr-`, `text-left`, `text-right`, `left-*`,
  `right-*` anywhere this phase touches. A repo-wide grep (`pl-|pr-|ml-|mr-|text-left|text-right|
  left-\[|right-\[`) across `app/` and `components/` returned zero matches this session [VERIFIED] —
  the invariant has held for 5 phases; this phase is the first to actually runtime-test it and must not
  be the one that breaks it.
- Plain `flex` row layouts already reverse correctly under `dir="rtl"` automatically — never add
  `flex-row-reverse` to compensate (that would double-flip).
- None of this phase's new icons (`Heart`, `Bell`, and whatever glyph the language switcher may add,
  if any) carry inherent left/right directionality — no icon-mirroring transform is needed (contrast
  with, e.g., a "back" chevron, which this phase does not introduce).
- **Assumption flagged for build-time visual verification:** Base UI's `Popover` `align="end"` is
  expected to resolve relative to the ambient `dir` context (mirroring under RTL automatically, the
  same way Radix-family primitives do), so the notification dropdown should still anchor correctly
  under the bell in Hebrew — this was not independently fetched from Base UI's own docs this session,
  so confirm visually once Hebrew is active that the dropdown doesn't overflow past the viewport edge.
