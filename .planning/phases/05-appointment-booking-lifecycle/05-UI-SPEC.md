# Phase 05 — UI Design Contract

> Visual and interaction contract for `/patient/appointments`, `/doctor/appointments`, the booking
> confirmation modal, the reschedule slot-picker, and the cancellation confirmation modal
> (Appointment Booking & Lifecycle). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase adds no new visual system. It is a pure extension of the design language
already shipped in Phase 3 (`app/doctors/[id]/page.tsx`'s day-grouped slot list, the now-enabled
"Select this slot" button, `lib/timezone.ts` formatting) and Phase 4 (`app/doctor/(gated)/schedule/page.tsx`'s
Dialog-based confirm/form pattern, status-badge variant convention, destructive-trigger-then-confirm
flow). This contract locks how those existing patterns compose for booking, cancelling, rescheduling,
and the two new appointment-history pages — not a new design system.

Declared values (must be multiples of 4), matching every prior phase's usage:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside a badge |
| sm | 8px | Compact stacked spacing (label-to-input, badge-to-reason-line) |
| md | 16px | Default element spacing (form field-to-field, dialog body gap) |
| lg | 24px | Section padding, gap between "Upcoming" and "Past" sections |
| xl | 32px | Gap between page header and the first section on `/patient/appointments` / `/doctor/appointments` |

| 3xl | 64px | Page-level spacing (not expected at typical demo-data volume) |

Exceptions (both already established elsewhere in the codebase — reused, not invented):
- **12px (`gap-3`)** — compact horizontal pairing of a time range with its status badge and action

- **44px (`min-h-11`) minimum touch target** — every actionable button this phase adds ("Select this
  slot", "Confirm booking", "Reschedule", "Cancel appointment", "Keep appointment", per-slot "Select
  this slot" inside the reschedule picker) must be at least 44px tall, matching the existing
  `min-h-11` convention already used for the (now-enabled) "Select this slot" button and Phase 4's
  Delete button.

## Color

Neutral (grayscale) shadcn theme — no brand hue exists in this project's tokens; "accent" below means
the primary near-black token, not a colored highlight. Identical palette to Phases 2-4.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` white) | Page background |
| Secondary (30%) | `--secondary` / `--muted` (`oklch(0.97 0 0)` light gray) | Dialog bodies, muted/help text, skeleton rows, the "Past" status badge |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)` near-black) | Reserved for: the "Select this slot" button on `/doctors/[id]` (now enabled — the entry point, D-01), the "Confirm booking" button inside the booking confirmation modal (D-02/D-03), each per-slot "Select this slot" button inside the reschedule picker (D-07), the "Confirmed" status badge on an upcoming appointment row, and the "Find a doctor" empty-state CTA on `/patient/appointments` when the patient has zero appointments |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)` red) | Reserved for: the "Cancel appointment" trigger button on any appointment row, the "Cancel appointment" confirm button inside the cancellation modal, and every server-rejected-write error message (slot no longer available, appointment can no longer be rescheduled/cancelled, past-slot, wrong-doctor) |

Accent reserved for exactly one prominent action per screen — never two competing default-variant
buttons visible at once, continuing the discipline set in Phase 4's `Add slot`/`Block period` split
(default vs. outline). "Reschedule" is `variant="outline"` (secondary tier, equal functional
importance to Cancel but visually subordinate to the slot-selection actions that own the accent
budget); "Keep appointment" (the cancel dialog's dismiss action) is `variant="outline"`; "Retry" on
any list-load error is `variant="outline"`, matching every prior phase's Retry precedent.

## Layout — Booking flow (D-01/D-02/D-03/D-04/D-05)

**Focal point:** the "Select this slot" button (entry to the booking confirmation modal, reserved
accent color per Color).

On `/doctors/[id]`, the existing (now-enabled) "Select this slot" `<Button>` per slot row:

1. **Auth check on click, not on mount:** the click handler checks the current session via the
   existing browser Supabase client (`lib/supabase/client.ts`, cheap `auth.getUser()` call — no new
   endpoint needed). If no user, `router.push('/login?from=' + encodeURIComponent(currentPath))`
   immediately — **no dialog ever opens** for an unauthenticated visitor (resolves D-04's discretion
   point: the return-to-slot handoff degrades to "return to this doctor's profile," not a
   pre-selected slot, since `proxy.ts`'s `?from=` mechanism already round-trips a plain pathname
   with no extra infrastructure).
2. If authenticated, opens a `Dialog` (`DialogHeader`/`DialogTitle` "Confirm your appointment") whose
   body renders the doctor/specialty/date/time/location summary (Copywriting Contract), a
   `DialogFooter` with "Cancel" (`outline`) and "Confirm booking" (`default`, disables + label swaps
   to "Booking…" while in flight) — same dialog shape as Phase 4's Add-slot dialog.
3. On submit, `POST /api/appointments`. Server re-verifies availability per D-05 — the modal never
   assumes the slot list it was opened from is still accurate.
4. On success (`201`): `router.push('/patient/appointments?booked=1')`. The appointments page reads
   `booked=1` once and renders the success line (Copywriting Contract) in the same
   `role="status" aria-live="polite"` region convention Phase 4 uses for its status messages.
5. On failure: inline `Alert variant="destructive"` inside the still-open dialog with the matching
   Copywriting Contract message; the dialog stays open so the patient can retry or cancel.

## Layout — `/patient/appointments` and `/doctor/appointments` (D-16/D-17/D-18)

**Focal point:** the upcoming appointments section, or — when there are no appointments at all —
the page-level empty-state CTA.

Single-column page, `<h1>My appointments</h1>` (Display role) at the top, directly followed by the
`role="status" aria-live="polite"` message line (booking/reschedule/cancel success, or the list-load
error), then two stacked sections in this fixed order:

- **"Upcoming"** (Heading role, 18px/600) — rows where `start_at >= now()` AND status is not
  `cancelled_by_patient`/`cancelled_by_doctor`, sorted ascending by `start_at` (soonest first). Section
  is **omitted entirely** (no heading rendered) if empty.
- **"Past"** (Heading role, 18px/600) — everything else: elapsed-and-never-cancelled rows (labeled
  "Past") plus any cancelled row regardless of whether its `start_at` is future or past (D-14/D-17 —
  a cancelled appointment always shows its real cancellation status, never re-bucketed as "Upcoming"
  even if the cancelled slot's original time hasn't passed yet), sorted descending by `start_at`
  (most recent first). Section is **omitted entirely** if empty.
- If **both** sections are empty, render the single page-level empty state (Copywriting Contract)
  instead of two empty section headers.

**Per-row format** (`flex items-center gap-3`, matching Phase 3/4's slot-row precedent):
`{formatJerusalemDayHeading or short date} · {formatJerusalemTime(start)}–{formatJerusalemTime(end)}`
(Label role) — then the counterpart party's name ("with Dr. {full_name}" on the patient page, the
patient's `full_name` on the doctor page, Body role, muted) — then the status `Badge` (Copywriting
Contract) — then, **only on upcoming, non-cancelled rows**: "Reschedule" (`outline`, patient page
only — never rendered on the doctor page, since D-06/D-07 scope reschedule to the patient) and
"Cancel appointment" (`destructive`), both `min-h-11`. Past and cancelled rows render **no action
buttons at all** (omitted, not disabled — continuing Phase 3's established "omit rather than
disable an inert control" precedent).

## Layout — Reschedule picker (D-07/D-09/D-10)

Opened from the "Reschedule" button on an upcoming appointment row. `Dialog` (`DialogHeader`/
`DialogTitle` "Reschedule your appointment") body: a day-grouped list of the same doctor's other
currently-available future slots — **exact visual reuse** of `app/doctors/[id]/page.tsx`'s
`groupSlotsByJerusalemDay` rendering (day heading, then `{time}–{time}` + a "Select this slot" button
per row, `min-h-11`, `default` variant). No secondary confirmation step inside this modal — clicking
a slot's "Select this slot" button directly calls `PATCH /api/appointments/[id]/reschedule` (the
modal itself, opened via an explicit "Reschedule" click, already serves as the confirmation gate;
this avoids a modal-within-modal and matches the button's existing "click = commit" semantics already
shipped for the original booking CTA before this phase added the extra confirm step for *first-time*
booking specifically). While a request is in flight, that slot's button label swaps to
"Rescheduling…" and every other slot button in the list disables. Zero available other slots renders
the empty state (Copywriting Contract) instead of the list. Errors render as an inline
`Alert variant="destructive"` above the slot list.

## Layout — Cancellation confirmation (D-12/D-13/D-14)

Opened from the "Cancel appointment" (`destructive`) trigger on any appointment row, on either page,
by whichever party is viewing it. `Dialog` (`DialogHeader`/`DialogTitle` "Cancel this appointment?")
body: warning paragraph (Copywriting Contract, `text-sm text-muted-foreground`) then a `Textarea`
labeled "Reason (optional)" — no character limit, sent verbatim/untrimmed when non-blank. `DialogFooter`:
"Keep appointment" (`outline`) and "Cancel appointment" (`destructive`, disables + label swaps to
"Cancelling…" while in flight) — same shape as Phase 4's destructive-confirm dialog. On success, the
dialog closes, the row updates in place (status badge flips to "Cancelled by patient"/"Cancelled by
doctor", action buttons disappear), and the status region shows "Appointment cancelled."
