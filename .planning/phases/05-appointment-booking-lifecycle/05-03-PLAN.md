<objective>
Give a doctor the same view of their own appointment book that plan 05-01 gave the patient: a `GET /api/doctor/appointments` endpoint scoped to the session doctor, and a `/doctor/appointments` page splitting their appointments into Upcoming and Past with the same derived status labels. This expands plan 05-01's proven read path sideways to the second actor, reusing `requireDoctor()`, the admin route's join shape, and — critically — the exact same `splitAppointments()` and `appointmentBadge()` helpers, so the two history pages cannot drift apart on what "Past" means.

Purpose: the doctor's list is where the platform's data-minimisation boundary actually gets decided. The admin oversight route already selects the patient's email because platform administration needs it, and copying that select string wholesale into a doctor-facing route is the single most likely way this phase leaks personal data it never needed. Building the doctor read as a deliberately narrower select, and asserting the absence of the extra fields in a spec, is the point of doing it as its own slice.

Output: `GET /api/doctor/appointments`, the `/doctor/appointments` page under the existing gated route group with a navigation link from the doctor landing page, and `tests/e2e/appointment-history.spec.ts` covering both actors' history views and the cross-actor scoping.

Scope guard: this plan renders no action buttons on any row. The doctor's cancellation action is plan 05-05, which extends this page; no reschedule control is ever added to the doctor page at all (D-06, D-07). Nothing here writes to the database.

Flagged assumption (spec-less probe, §A): APPT-12 and APPT-13 both returned `unclassified` from the deterministic edge probe. Their edges are resolved by human-authored decisions — the upcoming/past split by D-18, the derived label by D-16/D-17, the ownership scoping by D-20 — plus the UI-SPEC Layout section, which resolves the one case none of the decisions names: a cancelled appointment whose slot time has not yet arrived belongs in `Past`, not `Upcoming`. That reading is asserted as a truth above so it cannot be re-decided differently on this page than on the patient page.
</objective>
