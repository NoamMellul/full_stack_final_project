Complete the session lifecycle: a logged-in user can see who they are and end their session from any protected page, and the session really is gone afterwards.

Purpose: AUTH-03 is the last of the three session verbs. Logging out through a Route Handler rather than from the browser is what actually clears the httpOnly cookies `@supabase/ssr` sets — a client-side sign-out cannot remove them.

Output: AUTH-03 delivered, plus the shared header that every protected page in every later phase renders.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `POST /api/auth/logout` | The request carries no trusted payload; identity comes only from the session cookies the server reads |
| Server Component -> browser HTML | The header embeds the signed-in user's own name into rendered markup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-13 | Spoofing | `app/api/auth/logout/route.ts` | high | mitigate | `signOut()` runs on the SSR server client so the `Set-Cookie` clearing headers land on the response; a browser-side sign-out cannot remove httpOnly cookies. Proven by the post-logout test that navigates back to `/patient` and asserts the redirect to `/login` |
| T-01-04 | Spoofing | `components/site-header.tsx` | high | mitigate | The header resolves identity with the network-verified `auth.getUser()`; the unrevalidated cookie-read accessor stays banned across `app`, `lib` and `components` |
| T-01-05 | Information Disclosure | `components/site-header.tsx` name lookup | high | mitigate | The `profiles.full_name` read runs on the session-bound server client, so `profiles_select_own_or_admin` restricts it to the caller's own row; the service-role client is asserted absent from `components` |
| T-01-14 | Information Disclosure | logout failure copy | low | accept | The failure message is a fixed contract string with no server detail, so it discloses nothing; no further control is warranted |
| T-01-15 | Elevation of Privilege | role layouts edited to add the header | high | mitigate | The header insertion is presentation-only; each layout is gated on still containing its `redirect("/login")` call and its role comparison, so a refactor cannot quietly drop the guard |
</threat_model>
