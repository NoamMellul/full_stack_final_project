<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any inbound HTTP request -> Next.js router | The single choke point where every request, authenticated or not, is first inspected |
| request gate -> role-scoped layout | Two independent authorization layers, neither allowed to assume the other ran |
| session cookie -> Supabase Auth | The cookie is attacker-supplied until Supabase revalidates it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Spoofing | root request-interception file | critical | mitigate | The gate is a root `proxy.ts` exporting `proxy()`, gated by both a file-existence assertion and a grep for the exported name, plus an assertion that the legacy filename is absent — under Next.js 16 the old name is ignored with no build error, so every protected route would render for anonymous visitors |
| T-01-16 | Spoofing | `lib/supabase/proxy.ts` session read | high | mitigate | The gate decides on the network-verified `auth.getUser()` called immediately after client construction with no intervening statements; the unrevalidated cookie-read accessor is banned across `app`, `lib` and `proxy.ts` |
| T-01-02 | Tampering | the `from` parameter emitted by the gate | high | mitigate | Only `request.nextUrl.pathname` is written into the parameter, never a full URL, and the consumer in `lib/validation/redirect.ts` independently rejects anything absolute or protocol-relative — the producer and the consumer are both constrained |
| T-01-17 | Elevation of Privilege | role enforcement | critical | mitigate | Defence in depth: the request gate blocks anonymous access and the role-scoped layout blocks cross-role access, backstopped by RLS `is_admin()` / `is_doctor_owner()` at the database. All nine role-versus-route combinations are asserted, not sampled |
| T-01-18 | Information Disclosure | `lib/supabase/client.ts` | medium | mitigate | The browser client is constructed only from `NEXT_PUBLIC_`-prefixed values; a negative grep asserts no service-role key name appears in the file, so the browser bundle can never carry the RLS-bypassing key |
| T-01-19 | Denial of Service | per-request `auth.getUser()` | low | accept | The gate adds one Auth round trip per matched request. Accepted for a Tel-Aviv-only demo deployment; the cheaper local-JWT alternative is recorded as an opt-out in COVERAGE.md because its prerequisite key configuration on the remote project is unverified |
</threat_model>
