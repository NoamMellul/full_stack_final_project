# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase surface (per objective):** `/signup` page, `/login` page (email/password forms), a logout action in a shared header, and role-scoped protected layouts for patient/doctor/admin (mostly empty shells — real dashboard content lands in Phase 6). No dashboards with real data, no data tables, no booking UI yet.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present, do not re-init) |
| Preset | `base-nova` style, `neutral` base color, `cssVariables: true`, `rtl: true` — set at project scaffold time, confirmed as-is (no color change proposed for this phase) |
| Component library | Base UI (`@base-ui/react`) — **not** Radix; confirmed by reading `components/ui/button.tsx` (`import { Button as ButtonPrimitive } from "@base-ui/react/button"`) |
| Icon library | `lucide-react` (already installed, `iconLibrary: "lucide"` in `components.json`) |
| Font | Geist Sans (UI text) / Geist Mono (code-like/mono contexts), via `next/font/google` in `app/layout.tsx` |

**Integration gap to fix before/while building this phase's UI:** `app/layout.tsx` currently names its Geist Sans font variable `--font-geist-sans`, but `app/globals.css`'s `@theme inline` block maps `--font-sans: var(--font-sans)` — a self-reference that never resolves to Geist Sans. Left as-is, body text silently falls back to the browser default sans-serif stack instead of Geist. Fix by either renaming the `next/font` variable to `--font-sans` in `app/layout.tsx`, or adding `--font-sans: var(--font-geist-sans);` under `:root` in `app/globals.css`. This is a plan/execution task, not a design decision, but must be resolved for the typography contract below to actually render.

**RTL note (does not block this phase, but constrains how it's built):** Full language-switching UI is out of scope for Phase 1 (lands in Phase 6), but `rtl: true` is already active in `components.json`. All layout/spacing classes written in this phase (`/signup`, `/login`, header, role layouts) must use Tailwind logical properties (`ps-`, `pe-`, `ms-`, `me-`, `text-start`, `text-end`) instead of physical ones (`pl-`, `pr-`, `ml-`, `mr-`, `text-left`, `text-right`), so no rework is needed when RTL switching ships later.

**No shadcn `Form` wrapper this phase:** shadcn's `Form` component assumes `react-hook-form` (+ typically a Zod resolver). Per D-02 (no schema library) and the small scope of this phase's forms, use plain shadcn primitives (`Input`, `Label`, `Button`, `Card`, `Alert`) with manual React state and the manual validation functions in `lib/validation/auth.ts` (already specified in `01-RESEARCH.md`) — not the `Form` primitive.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (e.g. logout icon + "Log out" text) |
| sm | 8px | Compact spacing: label-to-input gap, inline error text gap |
| md | 16px | Default spacing: form field stacking, card internal padding |
| lg | 24px | Auth card padding, section padding on dashboard shells |
| xl | 32px | Gap between auth card and page edge on desktop |
| 2xl | 48px | Vertical centering offset / major section breaks |
| 3xl | 64px | Page-level top spacing on wide viewports |

Exceptions: 44px minimum tap target for the icon-only logout button when the header collapses to icon-only below the `sm` (640px) breakpoint — accessibility floor (WCAG 2.5.5/2.5.8 target size), takes precedence over the 8-point scale for that one control.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 24px | 600 (semibold) | 1.2 |
| Display | 32px | 600 (semibold) | 1.2 |

Usage: Body = form helper text, paragraph copy, dashboard-shell body copy. Label = form field labels ("Email", "Password", "Full name"), inline error text weight target (color carries the error signal, not weight — errors stay 14px/400 actually, see note below). Heading = page titles ("Create your account", "Log in", role dashboard shell titles). Display = not used on `/signup` or `/login` (kept single-purpose, focused forms); reserved for the app wordmark/logo lockup in the shared header if a larger brand mark is added later.

Note: inline field error text uses the **Label** size (14px) but **regular** weight (400) and the destructive color token, not semibold — semibold is reserved for the field label itself, so the two are visually distinct at a glance.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` / `#ffffff` (`--background`) | Page background, auth card background |
| Secondary (30%) | `oklch(0.97 0 0)` / `~#f7f7f7` (`--secondary` / `--muted`) | Shared header background, dashboard-shell panel background, input borders (`--border` / `--input`, same near-white-gray family) |
| Accent (10%) | `oklch(0.205 0 0)` / `~#1a1a1a` (`--primary`) | Reserved for: the primary CTA button on `/signup` ("Create account") and `/login` ("Log in"), the focus ring (`--ring`) on any focused form control, and the inline text link between the two forms ("Already have an account? Log in" / "Don't have an account? Sign up") |
| Destructive | `oklch(0.577 0.245 27.325)` / red (`--destructive`) | Reserved for: inline field validation errors, the auth API error banner (invalid credentials, email already in use), and the logout-failure inline message — no delete/destructive user action exists elsewhere in this phase |

Accent reserved for: primary submit buttons (signup/login), focus-visible ring on inputs and buttons, and the single cross-link between the signup and login forms. Nothing else in this phase's UI (header logout button, dashboard-shell placeholder text, secondary/outline buttons) uses the accent color — this keeps the already-neutral, grayscale-first shadcn theme intentional rather than decorative, matching the "clean, professional/medical-adjacent, not flashy" project direction.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Signup: **"Create account"** · Login: **"Log in"** |
| Empty state heading | Role-scoped dashboard shells (patient/doctor/admin), Phase 1 placeholder: **"Nothing here yet"** |

| Error state | Field validation (mirrors `lib/validation/auth.ts`): "Email is required." / "Invalid email format." / "Password is required." / "Password must be at least 6 characters." / "Full name is required." — API-level: **"Incorrect email or password. Please try again."** (login) · **"An account with this email already exists. Try logging in instead."** (signup) · **"Could not log out. Please try again."** (logout failure, shown inline next to the logout control) |
| Destructive confirmation | None in Phase 1 — logout is a non-destructive, reversible action and needs no confirmation dialog; no delete-type action exists in this phase's scope |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Elements classified: `signup-form` (form), `login-form` (form), `header-nav` (nav, includes the logout `interactive-control`), `dashboard-shell` (static-content, ×3 for patient/doctor/admin). No `list-collection` or `media` elements exist in this phase's UI — `populated` and `zero-one-many` are therefore not applicable to Phase 1 and were not raised.

Applicable state considerations resolved: 10 covered, 6 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | signup-form, login-form | ✅ covered | Unfilled inputs show placeholder text only (no pre-filled values); submit button stays enabled but a client-side presence check blocks submission and surfaces the per-field "required" copy from the Copywriting Contract before any network call |
| loading | signup-form, login-form | ✅ covered | Submit button disables and its label swaps to "Creating account…" / "Logging in…" for the duration of the request, preventing double-submit |
| loading | header-nav | ✅ covered | Header is a Server Component rendered from the already-resolved session; no client-side loading state needed for the nav itself |
| error | signup-form, login-form | ✅ covered | Inline field errors and the API-level error banner render per the "Error state" row in the Copywriting Contract, in destructive color at Label size/regular weight |
| error | header-nav (logout) | ✅ covered | If `signOut()` fails, the logout control re-enables and shows "Could not log out. Please try again." inline (Copywriting Contract) |
| overflow | dashboard-shell | ✅ covered | Placeholder heading/body copy is short and fixed for Phase 1 (see Copywriting Contract); no dynamic content yet, so no overflow risk |
| long-text | dashboard-shell | ✅ covered | Same fixed, short placeholder copy — no long-text risk until real content lands in Phase 6 |
| partial | signup-form | 🧪 backstop | On submit with only some fields invalid/empty, only the offending field(s) show inline errors; already-valid fields keep their entered values (no full-form reset) — verify visually |
| partial | login-form | 🧪 backstop | Same partial-fill behavior as signup-form, verify visually |
| long-text | signup-form (full name), login-form (email) | 🧪 backstop | Long input values scroll within the fixed-width input field rather than expanding the card or breaking the layout — verify visually |
| overflow | header-nav | 🧪 backstop | On viewports <640px, the header collapses the logout control to icon-only (see Spacing Scale exception); above 640px, a long display name truncates with ellipsis rather than wrapping — verify visually |
| long-text | header-nav | 🧪 backstop | User's full name in the header truncates with `truncate`/ellipsis at a fixed max-width rather than wrapping to a second line — verify visually |
