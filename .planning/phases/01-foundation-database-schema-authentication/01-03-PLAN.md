Expand the proven signup slice into the login slice: one shared `/login` page that authenticates every role, routes each user to their own home base, and refuses to bounce anyone to an off-site URL. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `POST /api/auth/login` | Untrusted credentials and an untrusted `from` query parameter cross here |
| `/login` page -> browser navigation | A caller-controlled string is used to choose a navigation target |
| role layout -> Postgres RLS | The layout's role read is itself subject to `profiles_select_own_or_admin` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Tampering | `app/login/page.tsx` return-path handling | high | mitigate | Every navigation target passes through `safeRedirectPath` in `lib/validation/redirect.ts`, which rejects anything not starting with a single slash and anything containing a colon; covered by two explicit Playwright cases (absolute URL and protocol-relative) |
| T-01-08 | Information Disclosure | `app/api/auth/login/route.ts` | medium | mitigate | All four failure branches return the byte-identical string and the test asserts the wrong-password body equals the unknown-address body, so the endpoint is not a user-enumeration oracle |
| T-01-04 | Spoofing | `app/doctor/layout.tsx`, `app/admin/layout.tsx` | high | mitigate | Both guards decide on the network-verified `auth.getUser()`; the unrevalidated cookie-read accessor is banned across `app` and `lib` by a negative grep |
| T-01-07 | Elevation of Privilege | role folder naming | high | mitigate | `app/patient`, `app/doctor` and `app/admin` are asserted to be plain folders and the parenthesised route-group variants asserted absent, so the URL prefixes Plan 05's matcher depends on genuinely exist (RESEARCH Pitfall 3) |
| T-01-05 | Information Disclosure | `app/api/auth/login/route.ts` role read | high | mitigate | The `profiles.role` lookup runs on the session-bound server client, so RLS restricts it to the caller's own row; the service-role client is asserted absent from the login route and page |
| T-01-03 | Spoofing | `/login` brute force | medium | transfer | Supabase Auth's per-IP rate limit is the control; confirmed by the developer against the remote project in Plan 01's `user_setup` |
</threat_model>
